# 1.1.3.2 读写锁（Read-Write Lock）：共享读与独占写

当共享数据结构呈现明显的“读多写少”特征，且单次读操作本身耗时较长时，普通互斥锁会让多个纯读线程彼此排队。读写锁（Shared-Exclusive Lock）将访问模式拆分为两类：

* **共享读模式（Shared / Reader Lock）**：多个线程可以同时持有读锁并发读取共享状态，互不阻塞，只要当前没有写者持有或等待（视具体实现与公平策略而定）。
* **独占写模式（Exclusive / Writer Lock）**：写锁必须排他持有，不仅阻止其他写者，也会阻止所有读者进入，保证写修改的原子性与视图一致性。

### `std::shared_mutex` 与实现权衡

* **C++17 `std::shared_mutex**`：支持 `lock()` / `unlock()` 独占写锁，以及 `lock_shared()` / `unlock_shared()` 共享读锁，常配合 `std::shared_lock` 管理读侧生命周期。
* **内部状态与开销代价**：读写锁需要维护活跃读者计数、写者状态及等待队列，其原子操作与分支逻辑通常比普通 `std::mutex` 更重；如果读临界区极短或写操作频繁，读者计数原子更新甚至可能成为新的缓存行争用点。
* **写者饥饿（Writer Starvation）与公平性**：若实现偏向读者（Reader-Preferred），持续涌入的读线程可能让写线程长期拿不到写锁；若偏向写者或采用队列/阶段策略，则可能降低纯读吞吐。具体行为取决于标准库与底层操作系统实现。
