# 1.1.2.1 核心概念辨析：Data Race vs. Race Condition

> **简介**：在日常并发讨论中，人们经常把“数据竞争”和“竞态条件”混为一谈。但在系统设计与 C++ 标准语义中，它们处于不同的抽象层次，既可能同时出现，也可能各自独立存在。

---

在日常并发讨论中，人们经常把“数据竞争”和“竞态条件”混为一谈。但在系统设计与 C++ 标准语义中，它们处于不同的抽象层次，既可能同时出现，也可能各自独立存在。

### 什么是 Data Race（数据竞争）？

在 C++ 内存模型中，**Data Race** 是严格的底层内存访问语义概念。当满足以下所有条件时，即发生数据竞争：

1. 两个或多个线程**并发**访问同一个内存位置（通常指同一标量对象或相邻位域所在的内存单元）；
2. 这些访问中**至少有一个是写操作**；
3. 这些并发访问**没有通过同步原语建立确定的先后关系**（即既不是同一求值内的严格定序，也没有通过原子操作、互斥锁等建立 `happens-before` 关系）。

只要发生 Data Race，程序就触发了 **C++ 未定义行为（UB）**——哪怕你“看起来”只是改了一个 `int` 或 `bool` 标志位。

### 什么是 Race Condition（竞态条件）？

**Race Condition** 是更高层次的**逻辑与时序正确性缺陷**：程序的执行结果或状态转移依赖于多个线程/事件交错到达或推进的相对时序。

* 即使**完全没有 Data Race**（例如所有共享变量都受 `std::mutex` 保护，或者全部使用 `std::atomic` 原子操作），依然可能存在 Race Condition。
* 典型例子：
* **Check-Then-Act（先检查后行动）**：线程 A 判断队列非空（加锁读 `empty() == false` 后解锁），随后线程 B 抢先弹出最后一个元素，线程 A 再去 `pop()` 时假设队列仍非空，导致逻辑错误或异常。
* **Read-Modify-Write（读-改-写）逻辑交错**：多个原子操作各自是原子的，但组合起来的业务状态更新不是原子的（例如先读余额再扣款，两次独立原子操作之间状态已变）。



### 四者关系速查：Data Race、Race Condition、线程安全与可重入性

| 概念 | 关注的核心问题 | 与内存/调度的关系 | 常见误区 |
| --- | --- | --- | --- |
| **Data Race（数据竞争）** | 同一内存地址的并发读写是否缺乏同步定序 | 直接违反 C++ 内存模型，导致 **UB** | “只改一个 `bool` 或 `int`，就算乱一点也没事”——实际可能导致撕裂读、编译器优化吞掉循环或程序崩溃 |
| **Race Condition（竞态条件）** | 多线程交错执行时，业务/状态机时序是否依赖运气 | 即使无 UB，也会导致逻辑错误、丢事件或状态不一致 | “用了 `std::atomic` 或 `std::mutex` 就绝不会有竞态条件”——复合操作仍会交错 |
| **Thread Safety（线程安全）** | 函数/对象在多线程并发调用时能否维持不变式与正确行为 | 依赖内部同步、无共享可变状态或不可变设计 | “加了锁就一定线程安全”——还需考虑死锁、锁粒度、回调重入与异常安全 |
| **Reentrant（可重入性）** | 函数在执行中被中断并再次进入（同线程递归、信号处理、嵌套回调）时是否安全 | 不依赖静态/全局可变状态，不调用不可重入原语 | “线程安全等价于可重入”——某些线程安全函数内部用了不可重入的锁或静态缓冲 |
