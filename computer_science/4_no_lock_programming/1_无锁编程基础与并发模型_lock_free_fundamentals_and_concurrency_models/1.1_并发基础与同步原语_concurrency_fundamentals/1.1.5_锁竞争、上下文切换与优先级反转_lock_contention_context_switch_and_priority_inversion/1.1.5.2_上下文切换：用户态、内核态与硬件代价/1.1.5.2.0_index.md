# 1.1.5.2 上下文切换：用户态、内核态与硬件代价

**介绍**: > **简介**：当线程无法立即获取阻塞锁（或时间片耗尽、被更高优先级任务抢占）时，操作系统调度器会将其置为睡眠/就绪切换状态，触发上下文切换（Context Switch）。

当线程无法立即获取阻塞锁（或时间片耗尽、被更高优先级任务抢占）时，操作系统调度器会将其置为睡眠/就绪切换状态，触发**上下文切换（Context Switch）**。

## 自愿切换与非自愿切换

- **自愿上下文切换（Voluntary Context Switch）**：线程主动调用阻塞原语（如 `std::mutex::lock()` 争用失败进入内核等待、`std::condition_variable::wait()`、`sleep`、同步 I/O）放弃 CPU。
- **非自愿上下文切换（Involuntary Context Switch）**：线程仍在可运行状态，但因时间片用完、被高优先级线程抢占或 CPU 亲和性/负载均衡迁移而被调度器强行换下。

## 上下文切换的显性与隐性开销

上下文切换的代价不仅在切换瞬间，还体现在后续执行阶段的**隐性缓存污染**：

1. **寄存器与内核栈切换**：保存旧线程的通用寄存器、栈指针与程序计数器，恢复新线程上下文；若涉及用户态与内核态转换，还需处理特权级切换与内核栈上下文。
2. **TLB 与指令/数据缓存失效**：线程切换（尤其是跨进程或跨核迁移）会冲刷局部性良好的 TLB 表项、L1/L2 指令与数据缓存，导致切换后的最初几百甚至数千条指令出现大量 Cache Miss 和 TLB Miss。
3. **尾延迟（Tail Latency, p99 / p99.9）飙升**：对低延迟系统而言，平均延迟看似不高，但偶发的锁等待 + 内核唤醒 + 跨核调度会让 p99/p99.9 延迟出现数量级跳变。
