# 1.1.5.3 优先级反转：成因、危害与缓解机制

**介绍**: > **简介**：优先级反转（Priority Inversion）指高优先级线程因等待被低优先级线程持有的共享资源而阻塞，而此时又有中等优先级线程就绪运行，抢占了低优先级线程的 CPU 时间，导致低优先级线程迟迟无法释放锁，高优先级线程的等待时间被无限拉长。

**优先级反转（Priority Inversion）**指高优先级线程因等待被低优先级线程持有的共享资源而阻塞，而此时又有中等优先级线程就绪运行，抢占了低优先级线程的 CPU 时间，导致低优先级线程迟迟无法释放锁，高优先级线程的等待时间被无限拉长。

## 经典三线程场景

1. 低优先级线程 `L` 获取了互斥锁 `M`。
2. 高优先级线程 `H` 就绪并抢占 `L`，随后尝试获取 `M`，因 `M` 被 `L` 持有而阻塞让出 CPU。
3. 中等优先级线程 `M_prio` 就绪，其优先级高于 `L`、低于 `H`；调度器优先运行 `M_prio`，使 `L` 得不到 CPU 时间片推进临界区、无法释放锁 `M`。
4. 结果 `H` 被间接阻塞在 `M_prio` 之后，优先级关系发生反转。

## 常见缓解与工程手段

- **优先级继承（Priority Inheritance）**：当高优先级线程阻塞在低优先级线程持有的锁上时，调度器/同步原语临时将低优先级线程的有效优先级提升至等待者（或更高）的优先级，帮助它尽快跑完临界区并释放锁；释放后恢复原优先级。
- **优先级天花板（Priority Ceiling）**：为互斥锁设定一个“天花板优先级”（不低于所有可能获取该锁的线程的最高优先级）；线程持有该锁时提升至天花板优先级，可防止部分优先级反转与死锁变种，但需注意系统支持与配置成本。
- **架构层规避（无锁 / 单写者 / 有界等待）**：在高频热路径上尽量避免高优先级实时/低延迟线程与低优先级后台线程争用同一把普通互斥锁（例如通过无锁队列、双缓冲快照或优先级隔离设计减少阻塞依赖）。
