# 1.1.3.3 自旋锁（Spinlock）：忙等循环与适用边界

**介绍**: > **简介**：自旋锁在无法立即获取锁时，不主动让出 CPU 休眠，而是在用户态通过原子测试/交换（如 `atomic_flag::test_and_set` 配合退避/暂停指令）循环轮询（Spin），直到锁变为可用状态。

---

**自旋锁**在无法立即获取锁时，不主动让出 CPU 休眠，而是在用户态通过原子测试/交换（如 `atomic_flag::test_and_set` 配合退避/暂停指令）循环轮询（Spin），直到锁变为可用状态。

### 为什么自旋锁不是“万金油”？

* **省去休眠唤醒开销，但消耗 CPU 周期**：如果锁很快被释放（通常远短于一次线程上下文切换的时间），自旋锁能避免内核挂起与唤醒的延迟；但如果持锁时间较长或线程数超过可用 CPU 核心数，自旋线程会白白占满 CPU 时间片。
* **超额订阅与抢占风险**：在虚拟机、容器或高负载系统中，若持有自旋锁的线程被操作系统调度器抢占（Preempted），其他自旋等待的线程可能空转直到时间片耗尽，造成严重的性能退化甚至活锁/延迟尖峰。
* **缓存行乒乓效应（Cache-Line Ping-Pong）**：多个核心在同一个原子锁变量上高频执行读-改-写循环，会导致该缓存行在各核心缓存之间频繁无效化与回传，增加内存子系统负担。工程上常在自旋循环中加入指数/线性退避或架构级暂停提示（如 x86 `pause`、ARM64 `yield` / `std::this_thread::yield()`）。
