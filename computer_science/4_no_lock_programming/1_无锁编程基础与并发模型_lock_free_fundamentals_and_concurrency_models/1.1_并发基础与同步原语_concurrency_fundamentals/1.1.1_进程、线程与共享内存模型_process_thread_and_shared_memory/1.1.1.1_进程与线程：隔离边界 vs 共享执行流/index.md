在现代操作系统中，**进程（Process）**是资源分配、虚拟地址空间隔离与安全权限边界的基本单位；**线程（Thread）**则是 CPU 调度的基本单位。在多核处理器架构下，同一进程内的多个线程既可以由内核调度器分发到不同的物理核心/硬件线程上真正并行执行，也可以在单核或超额订阅（Oversubscription）场景下通过时间片轮转并发推进。

### 进程级资源与隔离边界

- **独立的虚拟地址空间与页表**：每个进程通常拥有自己独立的虚拟地址空间和页表映射。进程 A 的虚拟地址与进程 B 的相同虚拟地址指向不同的物理页帧，天然防止一个进程意外踩踏另一个进程的内存。
- **独立的系统资源与内核控制块**：进程通常拥有独立的打开文件描述符表（FD table，除非在创建时显式共享）、信号处理配置、用户/组凭证、工作目录以及内核调度实体。
- **跨进程通信（IPC）代价**：由于默认不共享地址空间，进程间交换数据通常需要借助管道（Pipe）、命名管道（FIFO）、Unix Domain Socket、消息队列、共享内存段或内核态消息机制。跨进程上下文切换不仅涉及寄存器保存/恢复，还可能伴随地址空间切换与数据拷贝，开销通常高于同进程线程切换。

### 线程级共享状态与私有执行上下文

同一进程内的多个线程隶属于同一个地址空间与资源视图，共享以下核心资源：

- **代码段（`.text`）与只读数据段（`.rodata`）**：所有线程执行相同的机器指令序列，访问相同的常量与字面量。
- **全局与静态存储区（`.data` / `.bss`）**：进程级静态/全局变量对所有线程可见（`thread_local` 除外）。
- **堆内存（Heap）**：由 `malloc` / `free` 或 `new` / `delete` 分配的动态内存位于共享地址空间内，线程 A 分配的对象指针只要传递到线程 B，线程 B 就可以直接解引用读写。
- **文件描述符等进程级句柄**：默认情况下，同进程线程共享打开的文件、Socket 等描述符，这也意味着关闭或读写同一个 FD 时需要考虑并发语义。

与此同时，为了能够独立被调度、独立执行函数调用并拥有独立的局部状态，**每个线程必须维护自己的私有执行上下文（Thread Context）**：

1. **CPU 寄存器状态**：指令指针/程序计数器（如 x86_64 的 `RIP`、ARM64 的 `PC`）、栈指针（`RSP` / `SP`）、帧指针（`RBP` / `FP`）、通用寄存器、浮点/向量寄存器以及状态寄存器。
2. **线程调用栈（Thread Stack）**：每个线程在创建时都会分配（或按需增长）独立的调用栈，用于保存函数返回地址、传入参数、局部自动变量以及被调函数保存的寄存器现场。若栈上局部变量的指针逃逸到其他线程，容易引发悬空访问或并发缺陷。
3. **线程局部存储（TLS, Thread-Local Storage）**：用于保存每个线程各自独立的静态生命周期实例，避免多个线程争用同一全局地址。
4. **调度属性与信号掩码**：线程 ID（TID）、调度策略与优先级、CPU 亲和性掩码（CPU affinity），以及线程级信号屏蔽字（`signal mask`）。
