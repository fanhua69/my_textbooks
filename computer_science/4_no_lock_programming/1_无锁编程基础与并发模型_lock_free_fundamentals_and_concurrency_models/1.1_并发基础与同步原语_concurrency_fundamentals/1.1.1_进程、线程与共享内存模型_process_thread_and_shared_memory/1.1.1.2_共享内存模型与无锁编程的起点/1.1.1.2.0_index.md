在共享内存模型中，多个线程直接通过内存地址读写共享对象（例如无锁环形缓冲区的读写索引、SPSC/MPMC 队列节点指针、工作窃取双端队列或全局状态标志）。

### 为什么共享内存不能只靠“直觉读写”？

在单线程顺序执行视角下，内存看起来像是一块整齐、按程序顺序更新的字节数组。但在多核并发与现代编译器/硬件优化下，这一直觉会被打破：

- **编译器优化与指令重排**：编译器在保证单线程语义的前提下，可能将变量缓存在寄存器中、消除看似冗余的读写，或调整不依赖的内存操作指令顺序。
- **多核缓存层次与存储缓冲（Store Buffer）**：现代 CPU 每个核心通常有私有的 L1 缓存、统一的 L2 缓存以及多核共享的 L3 缓存。当一个核心执行写操作时，在缓存行处于独占/修改状态前，写操作可能先进入写缓冲（Store Buffer）；其他核心在收到缓存一致性协议广播或刷新无效化队列（Invalidate Queue）之前，未必立刻观测到该写入。
- **不同架构的内存序强度差异**：例如 x86_64 具有较强的总存储定序（TSO，Total Store Order）特性，而 ARM64 等弱内存序架构允许更多类型的读/写重排，若缺少明确的内存序约束，在 x86 上侥幸通过的并发代码可能在 ARM64 上出现难以复现的竞态或乱序观测。

### 从“数据存储”到“同步通道”的视角转变

无锁编程的起点，是把共享内存地址看作**线程间传递状态与建立同步关系（Synchronizes-With / Happens-Before）的契约载体**：

- **数据竞争是未定义行为（UB）**：在 C++ 内存模型中，若两个线程并发访问同一个非原子内存位置，且至少有一个是写操作，同时两者之间既没有 `happens-before` 关系也未通过原子操作/互斥锁正确同步，即构成**数据竞争（Data Race）**，会导致程序产生未定义行为。
- **原子性与内存序的分工**：原子操作（如 `std::atomic`）保证读-改-写或加载/存储本身的不可分割性（避免撕裂读/写与丢更新），而内存序（如 `memory_order_acquire`、`memory_order_release`、`memory_order_seq_cst` 等）则规定相关读写在线程间的可见性与重排约束。
