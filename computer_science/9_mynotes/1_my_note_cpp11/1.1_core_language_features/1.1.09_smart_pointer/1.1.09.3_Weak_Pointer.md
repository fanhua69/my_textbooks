# 1.1.09.3 Weak Pointer

**介绍**: Weak Pointer

---


`std::weak_ptr`（C++11 引入）是配合 `std::shared_ptr` 使用的**非拥有型智能指针**。它指向由 `std::shared_ptr` 管理的堆对象，但**不增加强引用计数（`use_count`）**，从而解决**循环引用导致的内存泄漏**以及**安全访问可能已被销毁的对象**。

---

## 1. 核心机制：控制块与双计数

控制块（Control Block）中维护着两套计数：
* **强引用计数（`use_count`）**：归零时销毁托管对象（调用析构函数 / 自定义删除器）。
* **弱引用计数（`weak_count`）**：归零时才释放控制块本身的内存。

---

## 2. 基本用法：`lock()` 与 `expired()`

`weak_ptr` **不能直接解引用（没有 `*` 和 `->` 运算符）**，必须先调用 `lock()` 获取临时的 `std::shared_ptr`：

```cpp
#include <iostream>
#include <memory>

int main() {
    std::weak_ptr<int> wp;

    {
        auto sp = std::make_shared<int>(42);
        wp = sp; // 不增加 use_count，此时 use_count() == 1

        if (auto locked = wp.lock()) { // 提升为 shared_ptr，期间对象不会被销毁
            std::cout << "value = " << *locked
                      << ", use_count = " << locked.use_count() << '\n';
        }
    } // sp 离开作用域，强引用归零，int(42) 已被销毁

    std::cout << "expired = " << wp.expired() << '\n'; // 1 (true)
    if (auto locked = wp.lock()) {
        std::cout << *locked << '\n';
    } else {
        std::cout << "target has been destroyed\n";
    }
}
```

> **线程安全提示**：不要先写 `if (!wp.expired()) { auto sp = wp.lock(); ... }`。多线程下 `expired()` 返回 `false` 后、调用 `lock()` 之前，另一个线程可能刚好析构了最后一个 `shared_ptr`。直接 `if (auto sp = wp.lock())` 才是原子的。

---

## 3. 典型场景一：打破循环引用

父节点持有子节点的 `shared_ptr`，子节点若要回溯父节点，应使用 `weak_ptr`：

```cpp
#include <iostream>
#include <memory>

struct Child;

struct Parent {
    std::shared_ptr<Child> child;
    ~Parent() { std::cout << "~Parent\n"; }
};

struct Child {
    std::weak_ptr<Parent> parent; // 打破循环引用
    ~Child() { std::cout << "~Child\n"; }
};

int main() {
    auto p = std::make_shared<Parent>();
    auto c = std::make_shared<Child>();
    p->child = c;
    c->parent = p;

    if (auto parent_sp = c->parent.lock()) {
        std::cout << "child has valid parent\n";
    }
} // 正常析构，输出 ~Parent 和 ~Child


#include <iostream>
#include <memory>

int main() {
    std::weak_ptr<int> wp;

    {
        auto sp = std::make_shared<int>(42);
        wp = sp; // 不增加 use_count，此时 use_count() == 1

        if (auto locked = wp.lock()) { // 提升为 shared_ptr，期间对象不会被销毁
            std::cout << "value = " << *locked << ", use_count = " << locked.use_count() << '\n';
        }
    } // sp 离开作用域，强引用归零，int(42) 已被销毁

    std::cout << "expired = " << wp.expired() << '\n'; // true (1)
    if (auto locked = wp.lock()) {
        std::cout << *locked << '\n';
    } else {
        std::cout << "target has been destroyed\n";
    }
}

```

---

## 4. 典型场景二：观察者 / 回调与弱缓存

* **观察者 / 事件回调**：事件中心保存 `std::weak_ptr<Listener>`；派发事件时 `lock()`，若已失效则移除，避免向已销毁对象发通知。
* **弱缓存**：缓存池保存 `std::weak_ptr<Resource>`，外部还在持有 `shared_ptr` 就复用，没人引用时自动释放，避免缓存无限膨胀。

---

## 5. 常见坑点

1. **直接 `*wp` 或 `wp->`**：无法通过编译，必须先 `lock()` 判空。
2. **在对象内部获取自身的 `shared_ptr`**：类需公有继承 `std::enable_shared_from_this<T>` 并调用 `shared_from_this()`（前提是对象本身已由 `shared_ptr` 托管）。
3. **控制块生命周期长于对象**：只要还有 `weak_ptr` 存活，控制块就不会释放；使用 `std::make_shared` 时，对象析构后整块内存仍需等 `weak_count` 归零才释放。
