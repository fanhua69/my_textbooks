# 1.2.1.18.4 **4. 为什么不能直接修改原来的 Snapshot？**

**介绍**: **4. 为什么不能直接修改原来的 Snapshot？**

> **简介**：假设有三个查询线程：

---

假设有三个查询线程：

```
Thread 1 ──┐
Thread 2 ──┼──> Snapshot Version 100
Thread 3 ──┘
```

后台线程正在修改 User 1001 的权限。

如果直接修改：

```
snapshot.grant(1001, CME);
```

就可能出现：

- Thread 1 读取到了旧权限。
- Thread 2 读取到了更新一半的数据。
- Thread 3 读取到了新权限。

这会造成并发数据竞争，甚至导致查询结果不一致。

采用不可变快照：

```
                  ┌─────────────────┐
                  │ Snapshot V100   │
                  │ 只读            │
                  └─────────────────┘
                          ▲
                          │
             Reader 1, 2, 3
                          │

Background Worker
       │
       ▼
  构建 Snapshot V101
       │
       ▼
  Atomic Pointer Swap
       │
       ▼
                  ┌─────────────────┐
                  │ Snapshot V101   │
                  │ 只读            │
                  └─────────────────┘
```

这样，查询线程永远不会看到正在被修改的快照。

注意：原子指针切换保证的是发布过程的原子性，并不意味着所有查询线程在同一时刻切换。已经持有 V100 的查询线程可以继续完成查询。
