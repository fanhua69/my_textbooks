# 1.2.1.19.1 核心术语与英文缩写对照表

**介绍**: 核心术语与英文缩写对照表

---

为方便阅读，下文涉及的技术英文缩写及其全称、核心含义如下：

| 英文简称 | 英文全称 | 中文释义与技术注释 |
| :--- | :--- | :--- |
| **API** | Application Programming Interface | **应用程序编程接口**。系统对外暴露的服务调用入口。 |
| **RBAC** | Role-Based Access Control | **基于角色的访问控制**。权限分配给角色，用户通过关联角色获得权限的经典权限模型。 |
| **ABAC** | Attribute-Based Access Control | **基于属性的访问控制**。根据用户、资源、环境等多维属性动态计算是否允许访问的细粒度权限模型。 |
| **QPS** | Queries Per Second | **每秒查询率**。衡量系统每秒能够处理的查询请求数量，是评估高并发读性能的核心指标。 |
| **DB** | Database | **数据库**。持久化存储权限配置、角色关系等基础数据的底层存储系统（如 MySQL）。 |
| **RT** | Response Time | **响应时间**。系统从接收到请求到返回响应所消耗的总时间。 |
| **GC** | Garbage Collection | **垃圾回收**。自动内存管理机制（如 JVM 的垃圾回收），频繁触发会导致 CPU 飙升。 |
| **STW** | Stop-The-World | **全局停顿**。在执行垃圾回收等操作时，暂停所有应用业务线程的现象，会导致接口瞬间卡顿。 |
| **P99** | 99th Percentile Latency | **99 分位延迟**。表示 99% 的请求响应时间都低于该值，用于衡量系统在极端情况下的长尾延迟表现。 |
| **CDC** | Change Data Capture | **变更数据捕获**。实时追踪并捕获数据库中数据增删改变化的技术（如解析数据库日志）。 |
| **MQ** | Message Queue | **消息队列**。用于系统间异步通信、削峰填谷的中间件（如 Kafka、RocketMQ）。 |
| **Binlog** | Binary Log | **二进制日志**。数据库（如 MySQL）记录所有数据变更操作的底层日志文件，常用于主从复制和增量同步。 |
| **Delta** | Delta (Incremental Data) | **增量数据 / 差量**。借用数学符号 $\Delta$ 的概念，指代两次状态之间发生局部变化的那一小部分数据。 |
| **COW** | Copy-On-Write | **写时复制**。修改数据时不直接覆盖原内存，而是先复制一份副本进行修改，完成后再原子替换引用的无锁并发技术。 |
| **Pull / Push** | Pull Mode / Push Mode | **拉取模式 / 推送模式**。数据同步的两种机制：Pull 指消费端主动定时轮询获取；Push 指数据源发生变化时主动推送给消费端。 |
| **SQL** | Structured Query Language | **结构化查询语言**。用于访问和操作关系型数据库的标准语言。 |
| **ASC** | Ascending | **升序排列**。数据库查询排序关键字，表示数据按照从小到大的顺序排列。 |
| **CPU** | Central Processing Unit | **中央处理器**。计算机的核心运算硬件资源。 |
| **$\mu s$** | Microsecond | **微秒**。时间单位，$1\text{ 秒} = 1,000,000\text{ 微秒}$（$10^{-6}\text{ 秒}$），用于衡量极致内存操作耗时。 |
| **Trade-off** | Trade-off | **架构权衡**。在系统设计中，针对相互冲突的目标（如强一致性与高可用性）所做的取舍与平衡。 |

---

在现代高性能、高并发的分布式系统（尤其是权限系统、配置中心、路由网关等读多写少的场景）中，**异步增量同步**是一种极其核心的架构设计模式。

它的核心思想可以概括为：**数据库发生变化时，不立即阻断或通知所有查询线程去拉取更新，而是由独立的后台线程异步获取变更，仅对内存中的局部数据进行增量更新，最后通过无锁或低锁的方式安全地发布给前端查询线程使用。**
