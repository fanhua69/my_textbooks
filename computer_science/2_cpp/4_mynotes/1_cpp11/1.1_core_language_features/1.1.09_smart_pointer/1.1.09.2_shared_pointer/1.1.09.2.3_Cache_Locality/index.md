# 1.1.09.2.3 Cache Locality

**介绍**: Cache Locality

---

**缓存局部性（Locality of Reference / Cache Locality）** 是计算机体系结构中的核心原理：程序在执行时，倾向于重复访问相同的数据，或者访问物理地址相邻的数据。利用这一特性，CPU 将常用数据提前放入高速缓存（L1/L2/L3 Cache），从而大幅减少访问主内存（RAM）的延迟。

---

## 1. 两种核心局部性

### ① 时间局部性（Temporal Locality）
* **定义**：如果某个内存位置被访问了一次，那么在不久的将来它很可能再次被访问。
* **典型场景**：循环计数器（如 `for (int i = 0; i < n; i++)` 中的 `i`）、频繁调用的函数代码、热数据变量。
* **缓存策略**：将刚访问的数据保留在 Cache 中，采用 LRU（最近最少使用）等算法决定淘汰哪些旧数据。

### ② 空间局部性（Spatial Locality）
* **定义**：如果某个内存位置被访问了，那么与它物理地址相邻的位置在不久的将来也很可能被访问。
* **典型场景**：顺序遍历数组、顺序执行指令、访问结构体中相邻的字段。
* **缓存策略**：CPU 从内存读取数据时，不是按字节读取，而是按 **缓存行（Cache Line，通常为 64 字节）** 整块加载到 Cache 中。

---

## 2. 为什么 Cache Locality 如此重要？

不同存储层级的访问延迟存在数量级差异（以现代 CPU 为参考）：

| 存储层级 | 典型访问延迟 | 相对速度对比 |
| :--- | :--- | :--- |
| **CPU 寄存器** | ~0.25 ns (1 周期) | 极快 |
| **L1 Cache** | ~1 ns (3~4 周期) | 基准 |
| **L2 Cache** | ~3~5 ns (10~14 周期) | 慢 3~5 倍 |
| **L3 Cache** | ~10~20 ns (30~50 周期) | 慢 10~20 倍 |
| **主内存 (RAM)** | ~60~100 ns (200+ 周期) | **慢 60~100 倍** |

**核心结论**：一次 **Cache Miss（缓存未命中）** 导致去主内存取数，CPU 可能要空转等待上百个时钟周期，严重拖垮程序吞吐量。

---

## 3. 代码示例对比

### 示例 A：二维数组遍历（行优先 vs 列优先）
在 C/C++/Java/Rust 等语言中，二维数组在内存中是**按行连续存储（Row-Major）**的。

```c
// ✅ 缓存友好：按行遍历（空间局部性极佳）
// 每次加载一个 Cache Line（64字节，可装 16 个 int），后续 15 次访问全部 Cache Hit
for (int i = 0; i < N; i++) {
    for (int j = 0; j < M; j++) {
        sum += matrix[i][j];
    }
}

// ❌ 缓存不友好：按列遍历（大量 Cache Miss）
// 每次访问都跨越 M 个元素，几乎每次都会触发新的 Cache Line 加载，甚至挤出旧缓存
for (int j = 0; j < M; j++) {
    for (int i = 0; i < N; i++) {
        sum += matrix[i][j];
    }
}
```
