# 1.1.1.07 PACELAC_and_CAP

**介绍**: PACELAC_and_CAP

**CAP Theorem（CAP 定理）** 是分布式系统中的一个经典理论，由计算机科学家 Eric Brewer 提出。

CAP 分别代表三个概念：

| 字母 | 英文                  | 中文    | 含义                        |
| -- | ------------------- | ----- | ------------------------- |
| C  | Consistency         | 一致性   | 所有节点读取到的数据保持一致            |
| A  | Availability        | 可用性   | 每个请求都能得到非错误响应             |
| P  | Partition Tolerance | 分区容错性 | 网络发生分区、节点之间无法通信时，系统仍能继续工作 |

## **1. CAP 定理的核心**

CAP 定理指出：

**当分布式系统发生网络分区（Network Partition）时，Consistency 和 Availability 无法同时得到保证。**

也就是说，必须在 C 和 A 之间做取舍。

## **2. 举个例子：银行账户转账**

假设有两个服务器：

**Server A**

# **&#x20;$1,000&#x20;**

**Server B**

# **&#x20;$1,000&#x20;**

Network Partition

两个服务器之间网络断开

A 和 B 无法相互同步数据。

现在，用户在 Server A 上取走 $200。

Server A 的余额变成 $800。

但是 Server B 仍然是 $1,000。

这时有两种选择：

### **方案一：选择 CP（Consistency + Partition Tolerance）**

优先保证一致性。

- Server B 无法确认最新余额。
- 暂停部分读取或写入请求。
- 等待网络恢复、数据同步。

结果：数据一致，但部分请求无法正常完成。

### **方案二：选择 AP（Availability + Partition Tolerance）**

优先保证可用性。

- Server A 继续处理请求。
- Server B 也继续处理请求。
- 两边可能暂时返回不同的余额。

结果：服务保持可用，但数据可能暂时不一致。

[medium.com](https://medium.com/%40amitkumartiwari_24120/the-great-dilemma-between-consistency-and-availability-40dbffc22a42?utm_source=chatgpt.com)

注意一个非常重要的概念：

**CAP 并不是说一个系统只能选择 C、A、P 三者中的两个。**

更准确地说：

- 网络分区 P 是分布式系统必须面对的故障情况。
- 当 P 发生时，需要在 C 和 A 之间权衡。
- 如果网络正常，CAP 定理并不禁止同时实现 C 和 A。

## **4. CAP 与 PACELC 的关系**

| 理论     | 关注的问题                          |
| ------ | ------------------------------ |
| CAP    | 网络分区发生时，C 和 A 如何取舍？            |
| PACELC | 网络分区时 C/A 如何取舍；正常情况下 C/L 如何取舍？ |

PACELC 比 CAP 考虑得更全面，因为它还考虑了正常运行时的一致性与延迟之间的权衡。

**结合你研究的 Bloomberg Entitlement 系统：**

这个理论很值得研究。

例如，多个 entitlement server 通过异步增量同步（Asynchronous Incremental Synchronization）维护权限数据：

- 如果同步延迟，某些节点可能持有旧权限。
- 如果要求强一致性，可能需要等待同步，增加查询延迟。
- 如果优先保证低延迟，可能接受短暂的权限数据不一致。

这正是分布式系统设计中 C、A、L 三个维度之间的工程权衡。
