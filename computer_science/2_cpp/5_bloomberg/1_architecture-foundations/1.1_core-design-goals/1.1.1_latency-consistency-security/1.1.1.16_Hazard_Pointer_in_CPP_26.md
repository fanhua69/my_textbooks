# C++26 Hazard Pointer（险象指针）深度解析

在无锁（Lock-Free）并发编程中，**安全内存回收（Safe Memory Reclamation, SMR）** 始终是最棘手的问题之一。C++26 正式将 **Hazard Pointer（险象指针，提案 P2530 / P1121）** 纳入标准库（头文件 `<hazard_pointer>`），为高并发无锁数据结构提供了标准化的底层内存安全保障。

---

## 1. 背景痛点：为什么无锁编程需要 Hazard Pointer？

假设我们有一个无锁的单向链表或无锁栈，线程 A 正在读取节点 `ptr`，而线程 B 几乎同时将该节点从数据结构中移除并调用 `delete ptr` 释放内存：

1. **悬垂指针与 Use-After-Free**：线程 A 读取 `ptr->data` 时，内存已被线程 B 归还给操作系统，导致程序崩溃或数据损坏。
2. **ABA 问题**：线程 B 释放 `ptr` 后，线程 C 刚好分配了同一块内存地址并重新插入结构，导致线程 A 的 `compare_exchange`（CAS）误以为节点从未改变。
3. **为什么不用 `std::shared_ptr`？**
   - `std::atomic<std::shared_ptr<T>>` 在绝大多数平台上**并不是无锁的**（内部通常依赖全局互斥锁池），在高频读场景下存在严重的缓存行争用（Cache Line Contention）和性能退化。
   - Hazard Pointer 将昂贵的同步开销从“读路径”转移到了“内存回收路径”，实现了真正的无锁读取。

---

## 2. 核心原理与工作机制

Hazard Pointer 的核心思想非常直观：**“我要访问这个指针了，谁都别删；等我用完了，你们再看着办。”**

整个机制包含两个核心组件：

### 2.1 险象指针（Hazard Pointer, HP）
- 每个线程在读取共享原子指针前，先在线程局部或全局可见的 HP 槽位（Slot）中**发布（Publish）**它正准备访问的目标地址。
- **双重检查（Double-Check）协议**：
  1. 线程加载共享原子指针的值 `p = atomic_ptr.load()`。
  2. 将 `p` 写入自己的 Hazard Pointer 中。
  3. **再次验证** `atomic_ptr.load() == p`。如果不等，说明在发布 HP 之前 `p` 已经被修改或删除，必须重试；如果相等，则保证在 HP 清除前，没有任何线程会释放 `p` 指向的对象。

### 2.2 退休列表（Retire List）与扫描回收
- 当写线程从数据结构中移除节点 `old_ptr` 时，它**不能直接 `delete`**，而是调用 `retire()` 将其放入当前线程的“退休列表（Retire List）”中。
- 当退休列表中的对象数量达到一定阈值时，触发一次**扫描回收（Scan & Reclaim）**：
  1. 收集当前系统中所有活跃线程持有的 Hazard Pointer 地址，存入一个集合（或排序数组）。
  2. 遍历当前线程的退休列表：
     - 如果某个退休对象的地址**不在**活跃 HP 集合中，说明没有任何线程正在访问它，可以安全地执行 `delete` 销毁！
     - 如果**在**活跃 HP 集合中，则将其保留在退休列表中，等待下一次扫描再回收。

## 3. C++26 `<hazard_pointer>` 核心 API 详解

C++26 在 `std` 命名空间下引入了以下核心类型与函数：

### 3.1 `std::hazard_pointer_obj_base<T, D>`
所有需要被 Hazard Pointer 保护的自定义对象，都必须继承自此基类（CRTP 模式）。它内部嵌入了用于构建退休链表的指针以及自定义删除器（默认 `std::default_delete<T>`）。

```cpp
template<class T, class D = std::default_delete<T>>
class hazard_pointer_obj_base {
public:
    void retire(D d = D()) noexcept; // 将对象标记为退休，等待安全回收
    // ...
};
```

### 3.2 `std::hazard_pointer`
RAII 风格的险象指针句柄，管理着底层 HP 槽位的生命周期。构造时分配槽位，析构时自动释放槽位（支持移动语义，禁止拷贝）。

核心成员函数：
- `bool empty() const noexcept`：检查当前对象是否关联了有效的 HP 槽位。
- `T* protect(const std::atomic<T*>& src) noexcept`：
  **最核心的读取接口**。内部自动执行“加载指针 -> 写入 HP 槽位 -> 内存屏障 -> 再次校验 `src` 是否变化”的循环，返回安全受保护的指针。
- `bool try_protect(T*& ptr, const std::atomic<T*>& src) noexcept`：
  非循环版本的保护操作。尝试保护预先加载的 `ptr`，若 `src` 已变化则更新 `ptr` 并返回 `false`，适合需要自定义循环逻辑的场景。
- `void reset_protection(nullptr_t = nullptr) noexcept`：提前解除对当前对象的保护，无需等待 `hazard_pointer` 析构。
- `void swap(hazard_pointer& other) noexcept`：交换两个 HP 句柄。

### 3.3 `std::make_hazard_pointer()`
工厂函数，用于从默认或指定的 `hazard_pointer_domain` 中获取一个可用的 `std::hazard_pointer` 实例。

```cpp
std::hazard_pointer hp = std::make_hazard_pointer();
```

## 4. 完整实战示例：无锁并发配置热更新

下面是一个典型的“高频无锁读 + 低频原子替换写”场景，展示如何使用 C++26 Hazard Pointer 安全地更新全局配置对象：

```cpp
#include <atomic>
#include <hazard_pointer>
#include <iostream>
#include <string>
#include <thread>
#include <vector>

// 1. 继承 std::hazard_pointer_obj_base
struct ServerConfig : public std::hazard_pointer_obj_base<ServerConfig> {
    int max_connections;
    std::string endpoint;

    ServerConfig(int conn, std::string ep)
        : max_connections(conn), endpoint(std::move(ep)) {}

    ~ServerConfig() {
        std::cout << "[GC] Safely destroyed config: " << endpoint << "\n";
    }
};

// 全局共享的原子配置指针
std::atomic<ServerConfig*> g_config{new ServerConfig(100, "v1.api.example.com")};

// 读线程：完全无锁读取配置
void reader_worker(int id) {
    // 2. 获取一个 hazard_pointer 实例（可在循环外复用以减少槽位分配开销）
    std::hazard_pointer hp = std::make_hazard_pointer();

    for (int i = 0; i < 5; ++i) {
        // 3. 安全保护并加载指针
        ServerConfig* cfg = hp.protect(g_config);

        if (cfg) {
            // 在 hp 有效期间，cfg 绝对不会被其他线程 delete
            std::cout << "Reader " << id << " reads: " << cfg->endpoint
                      << " (max_conn=" << cfg->max_connections << ")\n";
        }

        // 4. 主动解除保护（也可以依赖 hp 析构或下一次 protect 覆盖）
        hp.reset_protection();
        std::this_thread::yield();
    }
}

// 写线程：热更新配置并安全退休旧对象
void writer_worker() {
    auto* new_cfg = new ServerConfig(500, "v2.api.example.com");

    // 原子替换全局指针
    ServerConfig* old_cfg = g_config.exchange(new_cfg, std::memory_order_acq_rel);

    // 5. 绝对不能直接 delete old_cfg！调用 retire() 交由系统在安全时机销毁
    if (old_cfg) {
        old_cfg->retire();
    }
}

int main() {
    std::vector<std::thread> readers;
    for (int i = 0; i < 4; ++i) {
        readers.emplace_back(reader_worker, i);
    }

    std::thread writer(writer_worker);

    writer.join();
    for (auto& t : readers) {
        t.join();
    }

    // 程序结束前清理最后一个全局对象
    ServerConfig* last = g_config.exchange(nullptr);
    if (last) {
        last->retire();
    }

    return 0;
}
```

## 5. 关键工程最佳实践与陷阱

1. **复用 `std::hazard_pointer` 实例**：
   `std::make_hazard_pointer()` 可能涉及向全局域注册槽位的原子操作。在循环或高频调用中，应在循环外部构造 `hp` 对象，内部反复调用 `hp.protect(...)` 和 `hp.reset_protection()`。
2. **禁止拷贝，注意生命周期**：
   `std::hazard_pointer` 仅支持移动语义。一旦 `hp` 析构或调用 `reset_protection()`，受保护的裸指针即刻失效，严禁将其缓存到局部作用域之外。
3. **支持多指针同时保护**：
   在遍历无锁链表时，通常需要同时保护 `prev` 节点和 `curr` 节点，此时需要创建两个 `std::hazard_pointer` 实例（`hp_prev` 和 `hp_curr`），并在推进指针时使用 `std::swap(hp_prev, hp_curr)` 避免额外的原子开销。
4. **注意内存序（Memory Ordering）**：
   `protect()` 内部自带强内存屏障（通常为 `seq_cst`），确保在读线程读取对象成员之前，HP 槽位的发布对所有写线程可见；写线程的 `retire()` 扫描也依赖相应的屏障来捕获最新的 HP 状态。

## 6. Hazard Pointer vs. RCU（C++26 双雄对比）

C++26 同时引入了 **Hazard Pointer (`<hazard_pointer>`)** 和 **RCU (`<rcu>`)** 两种安全内存回收机制，二者各有适用边界：

| 维度 | Hazard Pointer (`<hazard_pointer>`) | RCU (`<rcu>`) |
| :--- | :--- | :--- |
| **保护粒度** | **细粒度（单对象级）**：只保护特定指针指向的对象 | **粗粒度（临界区级）**：保护整个读临界区期间访问的所有对象 |
| **读端开销** | 每次保护指针需要一次写操作 + 内存屏障（略高于 RCU） | 读端几乎零开销（通常仅递增局部计数器或完全无操作） |
| **写端/内存占用** | **内存有界**：未被引用的对象很快被回收，受阻塞线程影响极小 | **可能内存膨胀**：若某个读线程被长时间阻塞，整个宽限期（Grace Period）内所有退休对象都无法释放 |
| **典型适用场景** | 细粒度无锁数据结构（如无锁队列、无锁哈希表、跳表） | 读多写少、遍历大型只读快照数据结构（如路由表、全局配置） |
