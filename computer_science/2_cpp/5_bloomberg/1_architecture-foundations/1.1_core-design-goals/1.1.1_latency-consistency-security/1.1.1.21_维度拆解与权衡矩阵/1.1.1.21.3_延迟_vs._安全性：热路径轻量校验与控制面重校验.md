# 1.1.1.21.3 延迟 vs. 安全性：热路径轻量校验与控制面重校验

**介绍**: 延迟 vs. 安全性：热路径轻量校验与控制面重校验

> **简介**：把复杂的安全逻辑塞进每一次微秒级查询热路径，会让延迟迅速恶化。更合理的分层是：

---

把复杂的安全逻辑塞进每一次微秒级查询热路径，会让延迟迅速恶化。更合理的分层是：
* **数据面热路径（Data Plane）**：只做最精简的资格判断（例如用户 ID + 资源/权限 ID 的内存索引或位图查询），避免复杂策略引擎、远程调用和动态内存分配。
* **控制面与准入阶段（Control Plane / Session Setup）**：完成身份认证、策略规则求值、订阅关系校验、数据校验与快照生成，把计算成本前置到变更传播或会话建立阶段。

| 权衡维度 | 偏向低延迟 / 高吞吐 | 偏向强一致 / 高安全 | 典型工程折中方案 |
| :--- | :--- | :--- | :--- |
| **数据读取位置** | 本地内存只读快照 / 索引 | 中心权威存储或强一致协调 | 后台增量同步 + 原子指针切换快照 |
| **并发控制方式** | 无锁读 / 分片 / 读多写少快照 | 强同步锁 / 分布式共识读 | 不可变快照 + 后台单写者或增量构建 |
| **权限撤销处理** | 依赖周期同步或异步广播 | 实时同步失效，超时即拒绝 | 变更推送 + 版本号校验 + 异常 Fail-Closed |
| **尾延迟表现** | P99 / P99.9 更稳定、可预测 | 易受网络抖动、锁等待与 I/O 影响 | 热路径零 I/O、零分配，控制面异步吸收波动 |
