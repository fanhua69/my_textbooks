## 设计背景与动机

C++ 的诞生直接源于 **Bjarne Stroustrup**（比雅尼·斯特劳斯特鲁普）在 1970 年代末的实践经验。

Stroustrup 在剑桥大学攻读博士期间，使用 **Simula** 编写分布式系统仿真程序。Simula 提供了优秀的类、继承和程序组织能力，非常适合大型软件的结构设计，但其运行效率过低，无法满足实际系统的性能需求。后来他改用 **BCPL** 重写，虽然性能大幅提升，却缺乏足够的抽象机制，导致代码难以维护。

1979 年，Stroustrup 进入 AT&T 贝尔实验室（Bell Labs）的计算机科学研究中心。他开始分析 UNIX 内核，并探索如何将其分布式运行在局域网中的多台机器上。在这一过程中，他需要一种既能高效操作硬件（像 C 一样），又能提供良好程序组织结构（像 Simula 一样）的语言。

于是，他决定在 **C 语言** 的基础上增加类似 Simula 的类机制。最初的实现是一个预处理器 **Cpre**，它把带有类的扩展 C 代码转换成普通 C 代码，再交由现有的 C 编译器处理。这个早期版本被称为 **“C with Classes”**（带类的 C）。

核心设计目标从一开始就非常明确：

- **效率优先**：不使用的特性不应带来运行时开销（后来被总结为 **零开销抽象原则**，*zero-overhead principle*）。
- **与 C 高度兼容**：尽可能保持 C 的语法和语义，使现有 C 代码和程序员能够平滑过渡。
- **支持多范式**：既支持面向过程编程，也支持面向对象和后来的泛型编程。
- **直接操作硬件**：保留指针、手动内存管理等底层能力，适合系统编程。

---

## 从 “C with Classes” 到 C++（1979–1985）

### C with Classes（1979–1983）

1979 年 10 月，Cpre 预处理器已经可以运行。到 1980 年，它已支持实际项目。

C with Classes 早期引入的主要特性包括：

- 类（class）与成员函数
- 派生类（简单继承）
- 公有 / 私有访问控制
- 构造函数与析构函数
- 内联函数（inline）
- 默认参数
- 友元（friend）
- 函数参数类型检查
- 赋值运算符重载

这些特性奠定了 C++ 面向对象的基础，同时严格遵循“不使用就不付费”的原则。

### 命名为 C++ 并扩展（1982–1985）

到 1982 年左右，语言已经积累了足够多的新特性，原有名称“C with Classes”不再合适。最初曾短暂使用过 “C84” 的名字，但最终由 Rick Mascitti 建议改名为 **C++**——借用 C 语言的自增运算符 `++`，寓意“C 的下一步”。

1983–1985 年间，语言迅速成熟，主要新增特性有：

- 虚函数（virtual functions）——实现运行时多态
- 函数与运算符重载
- 引用（references）
- `const` 关键字
- `new` / `delete` 运算符
- 作用域解析运算符 `::`
- BCPL 风格的单行注释 `//`

1985 年是一个重要节点：

- **Cfront 1.0** 发布（第一个商业实现，仍是一个前端，把 C++ 翻译成 C）
- Stroustrup 出版《**The C++ Programming Language**》第一版，成为事实上的语言定义

此时，C++ 已经从“给 C 加类”演变成一门独立的、具备完整面向对象能力的语言。

---

## 早期商业化与功能完善（1985–1998）

### Cfront 2.0 与更多特性（1980 年代末）

1989 年左右的 Cfront 2.0 引入了多项重要扩展：

- 多重继承
- 抽象类（纯虚函数）
- 受保护访问（protected）
- 成员指针
- 类型安全的链接
- 静态与常量成员函数
- 类特定的 `new` / `delete`

同时，模板（templates）和异常（exceptions）也开始进入语言。

### 标准化进程启动

随着使用规模扩大，不同实现之间的不兼容性问题日益突出。1989 年 ANSI 成立 C++ 委员会，1991 年 ISO 也加入，正式开启标准化工作。

这一时期最重要的外部贡献是 **Alexander Stepanov** 提出的 **标准模板库（STL）**。STL 将泛型编程的思想系统性地引入 C++，并最终成为标准库的核心组成部分。

### 第一个国际标准：C++98

1998 年，ISO 发布 **ISO/IEC 14882:1998**，即 **C++98**。这是 C++ 历史上第一个正式国际标准。它固化了当时已成熟的语言特性，并正式纳入 STL，使容器、迭代器和算法成为标准库的一部分。

2003 年发布了 **C++03**，主要是对 C++98 的缺陷修复，没有引入重大新特性。

---

## 现代 C++ 的开端：C++11 及以后

从 C++98 到 C++11 经历了漫长的 13 年。2011 年发布的 **C++11**（原名 C++0x）被广泛认为是“现代 C++”的真正起点。它引入了大量提升表达力、安全性和性能的特性：

- 移动语义（move semantics）与右值引用
- `auto` 类型推导
- Lambda 表达式
- 智能指针（`unique_ptr`、`shared_ptr` 等）
- 范围 for 循环
- `nullptr`
- `constexpr`
- 统一初始化
- 并发支持（内存模型、`thread`、`mutex`、`future` 等）

此后，委员会采用大约每三年发布一个标准的节奏：

| 标准   | 发布时间 | 主要方向                         |
|--------|----------|----------------------------------|
| C++14  | 2014     | 对 C++11 的完善与小幅增强        |
| C++17  | 2017     | 实用库增强、结构化绑定、`if constexpr` 等 |
| C++20  | 2020     | Concepts、Ranges、Modules、Coroutines、三路比较运算符 |
| C++23  | 2023     | 库完善、`std::print`、`std::expected` 等 |
| C++26  | 预计 2026| 反射、契约、执行模型等（仍在演进中） |

现代 C++ 在保持底层控制能力的同时，显著提高了抽象层次和代码安全性，使“用 C++ 写得像高级语言，却能跑出接近 C 的性能”成为现实。

---

## C++ 与 C 的关系

C++ 被设计为 **C 的几乎超集**（almost a superset of C）。

主要兼容原则包括：

1. **语法与语义兼容**：绝大多数合法的 C 代码可以直接作为 C++ 代码编译（或只需极少量修改）。
2. **底层能力保留**：指针、手动内存管理、位操作等系统编程所需的能力完整保留。
3. **渐进增强**：程序员可以继续使用 C 风格编程，也可以逐步引入类、模板、RAII 等更高层的抽象。
4. **零开销承诺**：C++ 新增的抽象机制在不使用时不应引入额外运行时成本。

需要注意的是，C++ 并非 100% 兼容 C。例如：

- C++ 有更严格的类型检查
- 某些 C 的隐式转换在 C++ 中是非法的
- `void*` 的使用方式有所不同
- 关键字冲突（如 `class`、`new`、`template` 等）

尽管存在这些差异，C++ 与 C 的紧密关系使其能够无缝调用 C 库，并在系统软件、嵌入式、游戏引擎、高性能计算等领域长期占据重要地位。

---

## 总结

C++ 的发展历程可以概括为：

1. **1979**：从“给 C 加类”的实用需求出发（C with Classes）
2. **1985**：正式命名为 C++，具备完整面向对象能力并商业化
3. **1998**：完成第一次标准化（C++98），STL 成为标准库核心
4. **2011**：C++11 开启现代 C++ 时代，大幅提升语言表达力与安全性
5. **2011 至今**：以约三年一个标准的节奏持续演进，不断吸收现代编程语言的优秀思想，同时坚守“零开销抽象”与“对 C 兼容”的核心原则

理解这段历史，有助于更好地把握 C++ 的设计哲学，以及为什么它能在近半个世纪后依然活跃在对性能和可控性要求极高的领域。
